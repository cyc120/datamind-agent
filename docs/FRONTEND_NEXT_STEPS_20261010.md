# DataMind Agent 新版前端浏览评估与后续功能建议

- 日期：2026 年 10 月 10 日
- 评估对象：新版 Vue 首页与问数工作台
- 浏览地址：`http://127.0.0.1:8000/`
- 文档性质：基于本次页面体验与源码核对的建设建议，功能尚未按本文实施。

前端退役补充（2026-10-10）：旧版 `web/index.html`、`web/app.js`、`web/multifile.js`、`web/style.css` 已从工作区删除，旧版流程和专项 UI 测试可从 Git 历史查阅。本文保留本次浏览结论；后端 API 与新版 Vue 源码、构建产物继续保留。

## 1. 建设方向

新版已经具备首页介绍、自然语言提问、流式执行过程、SQL 结果表、引用卡片和可点击证据星图。下一阶段应重点补齐数据管理、证据查阅、历史回放和连续追问，让用户能够完成“选择数据 → 提问 → 核查依据 → 继续分析 → 保存结果”的完整流程。

优先顺序建议：**基础显示与导航修复 → 证据查阅 → 运行记录 → 数据与文件 → 连续追问 → 工业核验与设置 → 首页场景展示和结果导出。**

## 2. 本次浏览范围与发现

本次查看了首页、工作台的默认窄屏布局与桌面布局，并实际运行了以下三个示例：

| 场景 | 体验问题 | 页面表现 |
| --- | --- | --- |
| 零售问数 | 2025 年销售额最高的前三个产品是什么？ | 成功返回 3 行结果；点击 SQL 星点能够查看查询详情 |
| 文档问答 | 七天无理由退款的条件是什么？ | 返回答案和引用标题；引用原文与页码没有显示 |
| 工业核验 | 2026 年 9 月 A102 工序 30 哪些批次温度超限？生产记录和质检报告是否一致？ | 返回核验摘要和 48 个证据节点；摘要提到核验表，但页面没有呈现该表 |

这些体验仅用于判断前端流程与显示情况，不构成模型准确率、性能或生产可用性的评测。

## 3. P0：新增功能前优先修复

| 问题 | 用户影响 | 修复建议与验收要求 |
| --- | --- | --- |
| 首页区域导航进入空白页 | 用户无法顺畅查看原理、能力等介绍 | 实测点击“原理”后进入 `#/principle` 空白页。应协调页面锚点与 hash 路由；逐一验证各区域导航能够滚动到正确位置 |
| 浅色主题适配不完整 | 工作台答案、标题和输入提示难以阅读 | 统一文字、背景、按钮、表格与侧栏颜色；桌面和窄屏下正文及主要操作均清晰可辨 |
| 引用原文与页码缺失 | 用户看到了来源名称，却不能核查答案依据 | 对齐接口的 `quote`、`page_start`、`page_end` 等字段，并呈现原文件、原页入口；引用卡片能够显示原文、页码和版本 |
| 核验表未呈现，部分节点详情取值错误 | 工业摘要缺少可检查的明细，字段与核验节点可能为空 | 接入 `industrial_result`；修复节点详情按字段名读取的逻辑，核查实际证据载荷。点击字段或核验节点能看到相应明细 |
| 窄屏直接隐藏证据区 | 核心证据能力在较窄窗口中不可访问 | 提供“查看证据”按钮，以抽屉、标签页或全屏面板打开；窄屏仍可查看 SQL、引用与节点详情 |
| 模型接入状态缺少实际依据 | 后端在线被误认为模型已经可用 | 将服务健康与模型配置、连接测试结果分别呈现；没有检测结果时显示“未检测”，并展示最近检测时间 |

## 4. 后续新增或完善的区域与功能

### 4.1 数据与文件区域

**优先级：第一批。**

当前范围主要是演示数据库与知识库选项。建议新增独立“数据与文件”页面，并在提问区显示本次选中的数据范围。

建议内容：

- 可用数据库、知识库和文件列表，提供名称、用途及可查询内容说明。
- 文件上传入口，展示队列、处理进度、失败原因和后续操作。
- 分别呈现处理状态、复核状态和是否可检索；依据接口的可检索状态允许选择文件。
- 勾选一个或多个可用文件后提问，并在结果中显示哪些文件提供了支持证据、哪些文件未被引用。
- 用户切换范围时清晰提示当前选择，避免快捷示例实际使用的范围与下拉框显示不一致。

验收重点：用户能从文件进入问答，明确知道本次查了哪些数据；解析成功不能直接视为可检索。

### 4.2 证据查阅区

**优先级：第一批。**

现有星图已能点击，应进一步支持日常核查。

建议内容：

- 点击引用后打开原文预览，显示文档名称、版本、页码和相关片段。
- 接口提供有效定位信息时，高亮对应区域；无定位信息时保留文字证据并说明定位不可用。
- 点击答案中的引用编号，联动相关证据节点；点击节点可返回对应答案或来源。
- 增加按 SQL、文档、核验、冲突筛选，以及节点搜索、缩放和适应画布功能。
- 多条答案分别关联自己的证据图，查看旧答案时可恢复其对应证据。
- 为窄屏提供抽屉或全屏查看入口。

验收重点：从一条答案能够定位到支持它的具体数据或原文；节点较多时仍能找到目标证据。

### 4.3 运行记录与回放

**优先级：第一批。**

启用侧栏已有的“运行记录”占位入口。前端已有运行列表、事件和证据查询方法，后端已有相应接口，适合优先接入。

建议内容：

- 列出历史问题、时间、执行状态、数据范围和运行 ID。
- 支持按关键词、时间和状态查找记录，或输入运行 ID 打开。
- 打开历史记录时恢复答案、结果表、执行事件和该次证据图。
- 将“查看历史结果”和“重新执行”设计为两个明确操作；重新执行时生成新的运行记录。

验收重点：刷新页面后能够找回已完成分析；回放展示当次保存的结果，并保留相应来源版本信息。

### 4.4 连续追问与澄清

**优先级：第一批。**

当前页面保留多条消息，但提问请求没有传递历史。应接入后端已有的请求级历史与结构化澄清能力。

建议内容：

- 支持“只看华东”“换成去年”等追问，在后端支持范围内继承前文条件。
- 显示当前分析条件，如时间、区域、指标和数据范围，让用户能够检查继承结果。
- 缺少必要条件时展示候选按钮或补充表单，补齐后继续执行。
- 提供“新建对话”和清晰的范围切换入口；跨数据源或存在歧义时要求澄清。

验收重点：追问能够明确继承有效条件，歧义条件不会被静默猜测；每次结果仍保留独立运行与证据关联。

### 4.5 工业核验工作区

**优先级：第二批；核验表显示作为 P0 先完成。**

建议为工业场景提供独立工作区，先呈现结构化明细，再逐步接入复核与审批流程。

建议内容：

- 并列表格显示零件、批次、工序、测量值、报告值、标准限值、单位和依据来源。
- 分别标记超限、来源冲突、证据缺口和已按有效规则裁决的情况。
- 支持筛选异常项，并跳转到原始测量或报告证据。
- 接入字段复核、待审批事项、来源权威规则及其事件历史。
- 在后续阶段接入 CAD 与尺寸核验入口。

验收重点：摘要中的异常均有对应明细；未消解冲突保留双方原值，证据缺口不会显示为合格，审批遵循现有权限与独立审批约束。

### 4.6 模型与账户设置

**优先级：第二批；状态准确性作为 P0 先完成。**

启用已有“模型接入”占位入口，并补充登录与权限状态。

建议内容：

- 展示当前模型配置、可用配置及连接测试结果。
- 区分服务在线、模型已配置、测试成功和测试失败等状态。
- 展示当前账户、角色和与角色匹配的操作入口。
- 对配置修改、复核和审批等操作使用现有认证与权限机制。

验收重点：模型状态有真实检测依据；页面不回显已保存密钥，权限不足时给出明确说明。

### 4.7 结果工具条

**优先级：第二批。**

在答案与结果表附近增加轻量操作，便于将分析用于后续工作。

建议内容：

- 复制答案、复制 SQL、导出结果表。
- 保存或收藏分析，并从运行记录中重新打开。
- 依据字段含义展示金额、百分比、日期和单位；保留原始值可查。
- 导出答案时一并保留引用、运行 ID 和必要的来源信息。
- 运行期间提供明确进度和中断提示；仅在后端支持取消时提供取消执行操作。

验收重点：复制与导出内容完整且与当次结果一致，数值格式化不会改变原值或掩盖精度。

## 5. 首页建议新增：真实场景演示

在能力介绍与最终“开始体验”之间增加“真实场景演示”区域，采用三张场景卡。

| 场景 | 展示内容 | 进入体验后的行为 |
| --- | --- | --- |
| 零售分析 | 具体问题、结果表与 SQL 证据 | 打开工作台，选择对应数据范围并预填问题 |
| 文档问答 | 答案、引用原文和原页定位 | 打开对应知识库场景并预填问题 |
| 工业冲突核验 | 生产值与报告值差异、核验明细 | 打开工业核验场景并预填问题 |

场景卡应使用明确标注的演示数据或已有真实运行结果。首页星图若仅作静态展示，应标明“示意图”；若提示用户点击，则需提供相应详情交互。

若新增评测成果区域，只展示可追溯到报告的结果，并标明数据集、样本数、日期及适用范围，不将单次示例体验包装成准确率或生产效果。

## 6. 页面组织建议

建议侧栏逐步形成以下结构：

1. 问数与问答：提问、范围选择、答案与结果操作。
2. 数据与文件：数据说明、文件处理、可用状态和选择入口。
3. 运行记录：历史分析与回放。
4. 工业核验：核验明细、复核和审批；按权限展示。
5. 设置：模型配置、连接状态与账户信息。

桌面工作台保留“对话与结果 + 证据查阅”结构；窄屏用标签页或抽屉访问证据。上传管理、复杂审批和模型配置放到独立页面，避免主聊天页承载过多表单。
