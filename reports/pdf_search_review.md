# API 0.17 私有 PDF 检索审查

2026-10-07，基线 `6913ccc9a459b7bd91a72f72ec642d56e92d8a24`。

本阶段仅为已发布、显式选择的私有知识版本返回本地检索证据。管理员、CSRF/同源/no-store 和响应编码后的当前权限检查覆盖新 POST；不调用公开 RAG、生成模型，不写 publication/head/实际点，不执行 reset/删除。查询 profile 必须匹配完整本地模型文件/SDK/向量契约，缺失缓存与合成生产配置独立拒绝。

并行只读审查发现并补齐三处实质边界：

1. 轻量 admission 与完整行读取分离时，DB 计划可能在其间扩容。完整取行的同一 SQL 同时过滤剩余计划/元数据字节预算，避免先解码越界 JSON；实际冻结内容合计再校验。HTTP 测试实际扩容 JSONB，断言全计划 validator 未调用且返回 422。
2. 按文件分别访问向量时，检查最后文件期间第一文件点可能变化。共同 profile 的全部显式 ID 一次 retrieve 捕获；所有文件复核后再联合读回。测试实际在末尾文件复核后删除第一文档点，返回 409，不能用点数或写入 ack 放行。140 点实际单次 capture 和 514 点 SDK 前拒绝分别验证。
3. session backend 被终止后，PG 槽会释放而旧原生任务可能仍运行。查询/向量阶段与退出前探测连接，失去槽后拒绝返回，异常关闭连接；真实临时 DB backend 终止测试通过。不能把这个机制声称为能物理取消推理的硬 CPU 限额。

另有末尾 DB 摘要边界：只比保存的 SHA 标签会漏掉没有重写标签的 raw JSON 变动。取行与末尾联合 SQL 保存/比对 DB 自身 JSONB 文本 SHA，包含 publication 与 snapshot 全行；真实 JSONB 修改测试保留各标签不变，仍返回 409。此内部 DB 捕获摘要不替换外部完整持久计划 SHA，也不把内部 plan 自排字段摘要误用作客户端选择。

验证分层：profile/PG 槽专项 14/14，联合向量 8/8，HTTP 32/32，完整隔离 465/465，全部最终退出 0。专项依赖明确合成 embedding 或模拟 production-marked profile，实际 SDK/原生 PDF 验证与真实 BGE 场景分开。真实带 key Qdrant/本地 BGE 一个场景覆盖两文件、三发布、实际 query、来源链接、固定历史与缺缓存/错 key。没有生成模型质量评分、外部请求或下载。初始并发测试使用脱敏 DSN 导致 4 个认证错误，原日志保留，修正验证脚本后才通过。

完整性属于复核窗口，没有文件系统/PG/Qdrant 的分布式原子读取；可信存储操作者仍可后续修改内容。0.35 为未标定实验阈值，coverage 不代表支持用户问题或全文阅读。索引两槽与检索两槽独立，SQL/Qdrant 5 秒限额不等于完整请求 deadline/Python RSS 硬上限。生成模型出口、统一预算/硬隔离、PDF/OCR 解析队列、已发布存储修复、孤立回收和真实工业输入验收仍待推进。
